# 版本与交付定义

更新：2026-10-09。

| 名称 | 范围 | 当前状态 | 验收依据 |
|---|---|---|---|
| content-v0.1 | 2026-09-23 开放的公开知识内容首版 | 已开放，持续维护 | 飞书发布记录与当前可读取内容 |
| runtime-v0.1 | 用人工编排运行真实增长任务的最小系统 | 建设中，尚未验收 | 至少一个真实 Mission 的完整运行与反馈记录 |
| architecture v0.1 | 概念、对象和系统层的设计文档 | 已形成设计 | 文档可读；实现进度见项目和路线图 |

content-v0.1 是历史发布范围的名称，2026-10-09 补充这一命名以消除歧义。现有记录没有 Git tag 或 GitHub Release；这次命名不补造历史标签。后续内容变化写入飞书 Changelog，并用 Git 提交和飞书文档修订号定位具体快照。

runtime-v0.1 验收需记录一个真实任务的产品价值与目标，明确 Owner 和权限，设置检查点，保留 Context 与能力选择，记录 Run，交付可使用的 Artifact，再完成 Evaluation 和反馈回流。活动举行或内容数量不能单独满足验收，概念设计也不能。

单个模板、文章或能力包可以有自己的版本。引用版本时必须写明对象与范围，注明状态和验证证据。文件名中的 v0.1 表示该文件的设计版本；文件中的未来里程碑表示计划。

## 当前交付范围

GitHub 已提供项目定义与通用架构，也提供路线图和资源索引；飞书已开放知识正文与工具使用指南，并提供案例和需求入口。当前仓库 toolkit 目录只提供导航，尚未交付 Excel、Python、SQL 或 Notion 工具包。现有模板内容见[资源索引](content-index.md)。

未来交付按“计划中 → 已提供 → 已验证 → 已验收”记录。已提供需有可访问的实际资源；已验证需有指定场景下的使用证据；已验收需满足该对象声明的验收条件。
