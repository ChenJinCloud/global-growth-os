# 公开边界与版本决策

状态：现行。日期：2026-10-09。依据：陈今授权统一公开边界、版本定义并修复三端声明。

## 公开范围

Public Core 公开通用系统架构和可复用方法，也公开经授权、脱敏且标明证据范围的案例。四层内容架构继续用于读者导航；完整架构用于解释系统对象和运行设计。

团队实际运行实例保留在私有工作区。客户或成员身份与内部业务数据保留私有，凭证和访问权限也保留私有。生产运行状态及未获授权的原始素材不进入公开发布。既有付费报告的公开说明和预览可以保留，正文和交易权益按各资源声明执行。

本决策替代[2026-09-13 第一阶段策略](2026-09-13-public-phase1-four-layer-strategy.md)中“完整架构只留本地”的限制。原文保留为历史依据。现有架构公开表示设计可读，实现状态按[版本定义](../VERSIONING.md)和[路线图](../../ROADMAP.md)判断。

## 三端职责

| 位置 | 当前权威范围 | 更新要求 |
|---|---|---|
| 本地项目 | 项目状态、通用设计与私有工作材料 | 公共修订进入 Git；私有扩展保留本地 |
| GitHub | 审核后的公开项目定义、设计和目录 | 只提交明确选定的公共文件 |
| 飞书 | 已开放的知识正文、读者导航与 Changelog | 修改正文后保存本地快照，同步对应入口和交付声明 |

现有飞书正文没有全部转换为 GitHub Markdown。两端通过[资源索引](../content-index.md)关联；正文归属逐篇明确，禁止把索引一致写成全文同步完成。已有飞书正文以飞书修订为当前公开正文，本地快照用于核验与留存。未来迁入 Git 的正文需写明来源与修订号，注明迁移日期，再调整权威归属。

## 发布检查

发布前核对实际文件和链接，检查来源授权与隐私边界，写明资源的验证状态。发布后读取 GitHub 提交和飞书保存内容；若两端只统一入口，交付记录只声明入口统一。

公开原始材料必须获得对应授权。信源列表保存来源与引用范围；本地完整原文归档不随索引自动公开。历史文件中的活动计划和交付预测按当时记录阅读，不定义今天的状态。
