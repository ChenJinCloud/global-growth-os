# 拆解竞品爆发期 · 可执行手册

> **要研究一个竞品是怎么起来的，但不确定该看什么？** 1:1 增长咨询：把你的产品、参考对象和要决定的事发给我。联系方式见 [chenjin.io](https://chenjin.io)。

把「研究一下竞品」变成「一个能落地的验证动作」。**不是读完一篇分析，是填完六张卡，拿到一个下周就能做的动作。**

## 这套东西解决什么问题

研究竞品最常见的三种失败：

1. **看完什么都没变** —— 报告写得很长，但不知道自己要改什么
2. **把猜测当事实** —— "它火是因为定位准"，但拿不出证据
3. **样本一多就失控** —— 追了三十条帖子，最后总结不出来

这套流程用**六张卡**把研究压缩到最小闭环：一条发布帖、一次引用、一个验证动作。先跑通一轮，再决定要不要扩大。

## 核心原则（守住这三条，研究就不会白做）

**① 观察和解释必须分列。**
「原帖展示了整理前后的对比视频」是观察。「这种演示降低了理解成本」是解释。两张卡里永远分两行写，不混。

**② 一条证据一个编号。**
根帖是 `E01`，引用它的是 `E02`，后面所有判断都回指编号。别人能顺着编号找到原文。

**③ 取不到的写"未知"，不写零。**
拿不到曝光数据就写"未取得"，不要填 0，也不要留空假装没有。缺失本身就是结论的一部分。

## 5 分钟上手

1. 先填 **卡 1 任务说明**：写清"研究完成后我要决定哪一件事"。写不出来就先别做研究。
2. 填 **卡 2 窗口说明**：找出增长明显变化的时段，标出发布前/时/后。
3. 挑**一条**代表性发布帖，填 **卡 3 内容卡**，给它编号 `E01`。
4. 找**一次**引用转发（或一条评论），填 **卡 4 传播记录** + **卡 5 发现卡**。
5. 填 **卡 6 行动卡**：把发现改写成"在我自己的条件下做一个什么动作，怎么验证"。

**最小交付 = 六张卡放在同一个文件里。** 别人能顺着证据读懂你的判断，就合格了。

## 什么时候该扩大

只有当你需要解释**整个爆发期**（而不是单条帖子的效果）时，才用 `完整研究表.md`：

- 补一轮**没有直接转推官方帖**的独立讨论
- 保留**普通内容和负面反馈**，不只收高互动样本
- 把其他渠道、产品更新和后续运营放进同一条时间线

## 边界

- 外部能看到的是**传播痕迹**，看不到转化。不要用传播数据推断转化。
- 单个样本不能代表整体动机。
- 平台规则、票重、榜单机制会变，涉及平台机制时要重查当时规则。
- 这套方法产出的是**假设和验证计划**，不是因果结论。
