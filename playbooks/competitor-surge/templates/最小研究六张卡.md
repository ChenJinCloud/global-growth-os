# 最小研究 · 六张卡

> 复制整个文件，在「你的记录」列填写。中间列是虚构示范（参考产品 A 是在线流程图工具，自己的产品 B 能把截图转成可编辑流程图），只用来示范怎么填，不要照抄。
>
> 六张卡填完就是一个完整交付。

## 卡 1 · 任务说明

**要解决的问题**：把"研究一下竞品"改写成一个具体的工作问题。

| 填写项 | 虚构示范 | 你的记录 |

**可以进入下一步的标志**：你能说出"研究完成后，我要决定哪一件事"。暂时拿不到的数据另列，不阻止先开始。

## 卡 3 · 内容卡（根帖 `E01`）

**要解决的问题**：完整拆一条代表性发布帖，记录它怎样让读者理解产品。

> **根帖**：你开始追踪这次传播的那条原始帖子。可以是官方发布帖，也可以是与研究问题相关的用户原创帖。
>
> 先保存链接与必要截图。发布时间和数据采集时间**分开填**。

| 填写项 | 虚构示范 | 你的记录 |
| --- | --- | --- |
| 编号与原帖 | E01；［原帖链接］ | |
| 发布时间 / 采集时间 | D0 12:00 UTC+8 / ［采集时间］ | |
| 目标人群 | 需要整理和解释流程的办公人群 | |
| 开场与演示 | 草稿整理前后对比视频 | |
| 行动引导与数据 | 邀请试用；互动数据未取得 | |
| **观察事实** | 原帖展示了整理前后对比 | |
| **可能解释** | 这种演示可能降低理解成本，待核查用户反应 | |

**可以进入下一步的标志**：别人能打开你的原帖，找到你说的开场、演示和行动引导；观察与解释分开写。

## 卡 4 · 传播记录（互动 `E02`）

**要解决的问题**：追一次引用，找到与原帖不同的新增表达。

> **父节点**：某条互动直接回应或引用的那条帖子。E02 引用了 E01，E02 的父节点就是 E01。看不到关系就写"未知"。
>
> 评论、纯转发、引用转发要分开记：引用有新文案，能看出"分享者增加了什么"；纯转发只说明参与了扩散。

| 填写项 | 虚构示范 | 你的记录 |
| --- | --- | --- |
| 编号与父节点 | E02；父节点 E01 | |
| 互动类型与时间 | 引用转发；D0 14:00 UTC+8 | |
| 参与者与关系 | U01；公开简介为项目经理，与官方关系未知 | |
| 新增表达 | 这种前后对比很适合给客户解释流程 | |
| 来源与下游 | ［引用帖链接］；后续传播未观察到 | |

**可以进入下一步的标志**：你记录了一条可核查的关系（能点回原帖）。看不到引用时，改用一条评论，并注明它反映的是"回应"而不是"扩散"。

## 卡 5 · 发现卡

**要解决的问题**：把观察写成一条带证据和限制的判断。

| 填写项 | 虚构示范 | 你的记录 |
| --- | --- | --- |
| **观察事实** | E02 增加"向客户解释流程"的场景 | |
| **可能解释** | 可用于客户沟通的成果可能提供分享理由 | |
| **证据编号** | E01、E02 | |
| **未确认部分** | 单个样本不能代表整体动机；注册增长未确认 | |

**可以进入下一步的标志**：这条发现里有编号、有观察、有解释、有限制。缺任何一项都不算发现。

## 卡 6 · 行动卡

**要解决的问题**：把发现变成自己可以做的一个验证动作。

> **迁移假设**：把参考产品的发现，改写成"在自己的条件下，做这个动作可能带来什么变化"。它必须在自己的产品上验证。

先问两句：

- 我们的用户也有这个问题吗？
- 我们的产品能展示同样真实的价值吗？

| 填写项 | 虚构示范 | 你的记录 |
| --- | --- | --- |
| 参考发现与证据 | 客户沟通用途；E01、E02 | |
| 自己的适配条件 | 产品 B 转换结果可用，用户需要向客户说明流程 | |
| 具体动作 | 制作"流程截图 → 可编辑流程图"的对比视频 | |
| 负责人 / 素材 / 时间 | ［由执行者填写］ | |
| 验证方式 | 发布前给 5 位目标用户看，询问理解和用途，再邀请试用 | |
| 判断标准与后续 | 至少 4/5 人能准确说出用途；未达到先改演示 | |

**可以收尾的标志**：你有明确动作、所需素材、负责人和观察标准；无法确认的判断仍标为假设。

**最小交付**：六张卡放在同一份记录里。
