# 线下发布活动 Skill

把一场线下发布从"想法"推到"能办"。本 Skill 只做规划和检查，不代替你去现场。

## 什么时候用

- 要办一场 1–2 小时的线下产品发布 / 公测 / 用户测试
- 已经确定要办，但还没排出流程
- 快办了，想检查有没有漏项

不适用：纯线上发布会、概念验证阶段、需要严格保密的产品。

## 开始前必须问清的三件事

1. **日期与时长**（含到场时间）
2. **目标人群是谁、从哪来、目标人数**
3. **产品现在能演示到什么程度**（有没有可运行的东西、哪些只能放录屏）

这三样缺一个，就不要往下排流程。

## 执行步骤

### 第 1 步：定目标与人群

问用户：这场活动成功的样子是什么？要一句**可验证**的话，例如"现场 5 个人注册"或"拿到 10 条可用反馈"。

写不出可验证目标，说明活动目的还没想清楚，先停在这里。

### 第 2 步：出流程总表

读 [templates/流程总表.md](templates/流程总表.md)，按用户给的总时长重排时间轴。

固定规则：
- 实操和讨论的时间不可压缩，超时优先砍主讲
- 演示环节必须从会前问题池取题，不现场冷启动
- 必须有"当场合并"环节，否则活动没有落点

### 第 3 步：出宣发计划

读 [templates/宣发清单.md](templates/宣发清单.md)。

- 只选 2–3 个渠道做透，不要六个都发一半
- 第一篇必须在 **T-7** 之前发出
- 文案按渠道分别改写，不要一稿多投

### 第 4 步：出物料清单

读 [templates/物料清单.md](templates/物料清单.md)，按场地情况增删。

### 第 5 步：推进清单

用 [checklist.md](checklist.md) 逐项推进。每次对话开始时，先问用户"今天离活动还有几天"，然后只输出当前时间窗内的待办。

### 第 6 步：散场后复盘

按 `checklist.md` 的散场后与 T+2 部分执行。复盘必须包含：来了多少人、目标达成没有、哪一段最好、下次改什么。

## 输出格式

每次输出都要能直接拷走使用：

- 流程总表：表格，含时间、环节、内容、目的四列
- 文案：分渠道给出完整可发布文本，不留 `{{}}` 占位
- 清单：Markdown checkbox，可直接勾

## 边界

- 不替用户决定活动该不该办
- 不编造报名数据、到场人数或效果
- 引用真实案例时读 [case-aww26.md](case-aww26.md)，并保留其中"实际发生了什么"的诚实版本
