# 发布活动执行清单

按时间倒排。每项前面留空，做完打 `x`。「负责人」一列默认你自己，有协作者就填名字。

---

## T-7（活动前 7 天）

- [ ] **定目标**：这场活动成功的样子是什么？写一句可验证的话（例：现场 5 个人当场注册 / 收到 10 条可用反馈）。
  → 目标：______
- [ ] **定人群**：来的人是谁？从哪来？不请谁？
  → 人群：______
- [ ] **定规模**：目标人数 ___，场地容量 ___，报名目标 = 目标人数 × 1.6
- [ ] **定场地**：地址、到场时间、可用时长、投影/音响/网络
- [ ] **定主讲**：谁讲、讲多久、讲哪几段
- [ ] **开报名表单**，必须包含这两个问题：
  - 「你现在最卡的一件事是什么？」 ← 这就是现场问题池
  - 「你希望这场活动帮你解决什么？」
- [ ] **建活动群**，入群欢迎语写明时间、地点、到场时间
- [ ] **让 agent 起草流程总表**（用 `templates/流程总表.md`）

## T-3（活动前 3 天）

- [ ] **核对报名数**。低于目标 60% 就加推一轮
- [ ] **整理问题池**：把表单里的「最卡的事」归成 3–5 类，现场提问从这里出
- [ ] **预跑演示**：所有要现场演示的功能，完整跑一遍并录屏。**现场以预跑结果为主，不现场即兴操作**
- [ ] **备料**：投影转接线、翻页笔、便签、马克笔、组纸、举牌道具、签到表
- [ ] **排宣传**：至少提前 3 天发第一轮（见 `templates/宣发清单.md`）
- [ ] **确认议程手册**已发给所有执行者

## T-1（活动前一天）

- [ ] **走场**：到场走一遍动线，测投影、测网络、测麦克风
- [ ] **彩排开场 5 分钟**：开场是最容易垮的部分
- [ ] **打印**：签到表、议程手册、物料清单、分组纸
- [ ] **发提醒**：时间、地址、到场时间、需要带什么
- [ ] **准备合并模板**：如果活动有"当场采纳提案"环节，把提案→条目的格式提前做好
- [ ] **充电**：电脑、手机、录音设备

## 当天（T-0）

**到场前 60 分钟**

- [ ] 场地布置：座位、投影、签到台、物料就位
- [ ] 设备通电测试：投影、音响、网络、录音
- [ ] 大屏打开：议程页 / 产品页 / 待建清单页

**开场前 10 分钟**

- [ ] 签到开始，引导入座（按预设分组就座，别让人随机坐）
- [ ] 确认录音已开始

**活动中**

- [ ] 每个环节按流程总表走，超时就砍下一段，不压缩实操
- [ ] 每次演示结束举牌，❌ 立刻记进待建清单
- [ ] 分组讨论时只答"工具怎么用 / 这个名词什么意思 / 入口在哪"三类问题
- [ ] 合并环节只合并投票结果，不夹带自己的偏好

## 散场后（T+0 当晚）

- [ ] **合并记录入库**：投票数据、采纳的提案、待建清单
- [ ] **待建清单进下一版 roadmap**
- [ ] **加微信**：有质量的对话当场加，这是未来的种子用户名单
- [ ] **发一条感谢 + 结论**：说清采纳了什么、拒绝了什么、为什么
- [ ] **回收物料**，清点遗失

## T+2（两天内）

- [ ] **写复盘**：来了多少人 / 目标达成没有 / 哪一段最好哪一段最差 / 下次改什么
- [ ] **发对外复盘**（可选，但对外发复盘本身是最好的招人广告）
- [ ] **把这次的新模板回填进本手册**——活动会暴露模板缺的东西
