## 这套东西解决什么问题

办一场线下发布，真正难的不是写文案，而是三件事：

1. **现场冷场** —— 观众没问题问、没人举手、产品演示没人接得住
2. **反馈收不上来** —— 讲完了，大家说"挺好的"，然后没有下文
3. **讲完就散了** —— 活动结束，没有沉淀、没有线索、没有下一次

这套材料针对这三件事，把一场活动拆成五个阶段，每个阶段给出模板和判定标准。

## 5 分钟上手

1. 打开 [checklist.md](checklist.md)，把 T-7 那几项先排进日历。
2. 复制 `templates/流程总表.md`，按你的活动时长改时间轴。
3. 复制 `templates/宣发清单.md`，选 2–3 个渠道改文案。
4. 活动前一天照 [templates/议程手册.md](templates/议程手册.md) 走一遍。

## 三个关键设计（决定成败的地方）

**① 问题池必须在会前收，现场不能冷启动。**
报名表单里就问"你现在最卡的一件事"。现场前三问从池子里取，保证质量；观众临时提问是加菜，不是主菜。

**② 用举牌判定，把"翻车"变成产出。**
每个演示结束，全场举牌三选一：🤯 超预期 / ✅ 能用 / ❌ 不行。❌ 当场记进"待建清单"。
这一条把"我演示失败"重构成"我们在做用户测试"—— 主持人要说的是"好，这条进下一版"，不是辩解。

**③ 现场做一次"合并仪式"。**
让观众提案，全场投票，主持人当场把票数最高的 1–2 条并入产品，大屏显示 before / after。
参与感的来源不是礼品，是**看见自己的意见被写进去**。

## 边界

这套流程适合：目标用户能到场、产品已有可演示状态、你愿意当场承认不足。

不适合：纯线上发布会、还没成型的概念验证、需要严格保密的产品。
