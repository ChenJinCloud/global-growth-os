# Playbooks

可以直接拿走用的增长材料。每个 playbook 是一个独立目录，包含：说明、模板、清单、给 agent 的 SKILL，以及（有的话）一个脱敏案例。

**标准是"打开 5 分钟内能拷走一份文件开始填"，不是"读完理解了"。**

## 有什么

| Playbook | 解决什么 | 最小交付 |
| --- | --- | --- |
| [launch-event](launch-event/) | 办一场线下发布 / 公测活动，从筹备到散场 | 流程总表 + 议程手册 + 宣发文案 + 物料清单 |
| [competitor-surge](competitor-surge/) | 拆解一个参考产品的核心爆发期，落到一个验证动作 | 六张卡（任务/窗口/内容/传播/发现/行动） |

## 怎么选

- **要办活动** → launch-event
- **要研究别人怎么起来的** → competitor-surge

两件事经常连着做：先用 competitor-surge 看别人怎么发布的，再用 launch-event 办自己的。

## 每个 playbook 的结构

```
<name>/
  README.md       ← 3 分钟：解决什么、包含什么、怎么上手、边界
  SKILL.md        ← 给 AI agent 执行的流程
  checklist.md    ← 逐项打勾，最容易漏的地方在这里
  templates/      ← 空模板，复制后直接填
```

## 和飞书知识库的分工

- **飞书**：长文、方法论全文、画布、真实材料、证据档案
- **GitHub（这里）**：模板、清单、可执行步骤

同一主题在两处出现不是重复，形态不同：飞书那篇是"读完就懂"，这里这份是"拿走就用"。
