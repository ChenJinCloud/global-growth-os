## 一、这个实验是什么

**Growth OS**：一个从「不同人的共同需求」里长出来的增长知识库与工作流系统，公开建造、开源发布、可持续运转。

整个 OS 的项目定义见 [`../../project.md`](../../project.md)，完整系统架构与当前最小实现边界见 [`../../architecture/global-growth-os-concept-and-architecture-v0.1.md`](../../architecture/global-growth-os-concept-and-architecture-v0.1.md)。本文件只管理 AWW'26 公开实验、活动节奏与阶段验收，不承担整个 OS 的定义。

### 实验边界

- 本文件是 2026-09-10 至 2026-10-01 AWW'26 实验的唯一状态入口。
- `outputs/` 保存公测夜文案、流程、议程和后续复盘。
- Public Core 的建设工作流由 `../../public-core/` 管理。
- OS 全局阶段与优先级由 `../../ROADMAP.md` 管理。

- 它不是我的方法论输出，而是**采集 → 结构化 → 可被AI查询**的活系统
- 内容来源：我十年的信息获取与策展积累 + 表单采集的真实需求与卡点 + 贡献者的现场经验
- 形态：结构化知识库（AI可检索）+ 模块化工作流（SOP/Prompt/模板）+ 案例层（持续入库）

### 立项依据（2026-09-08 陈今自述）

1. 信息获取/策展能力已被外部验证（转发的内容也有人私聊认可）
2. 本身产出的内容获得认可
3. 知识库搭建是偏好且有意识（mentor：不是每个人都有这种需求和意识）
4. 2026年重构过知识库，个人OS管理是持续关注方向
5. 信息搜集能力可补偿 practice 不足：采集+copy高质量方案
6. 线下比线上更擅长帮人用起来
7. **核心目的：明确理念，搭一个能正常运转的系统，而非达成明确目标。v0.1 不必对，但必须能转**

### 核心产出：增长自动化机会图谱

每个案例/流程拆条：**AI已能干 / 差一步 / 永远要人**，双轴标注：
- **阶段轴**：0→1（自动化=降低行动门槛）vs 1→10（自动化=提效）——案例入库必采字段
- 长期价值：distribution engineer 论题的实证支撑 + agent-native backend 的 ICP 证据 + 可持续变厚的个人 IP 资产

## 三、9/24 活动设计（发布会+实操+反馈收集）

1. **开场（10min）**：Growth OS 是什么、怎么长出来的——14天建造史回顾（build in public 的帖墙本身就是叙事）
2. **Live Demo（25min）**：向 OS 提问，展示它能回答什么、不能回答什么——**诚实展示边界**（不能答的就是下一版的 roadmap，把缺陷变成参与理由）
3. **实操环节（40min）**：参与者每人把自己的真实情况带进来，**用 OS + AI 现场产出自己的第一步行动计划**——不是听我拆，是自己动手用
4. **反馈+共建（15min）**：缺什么、错什么、想加什么——现场收集进 roadmap，愿意贡献的扫码进 contributor

## 对标：AgentWork 社区（2026-09-08）

苍何的豆包工作蓝皮书 + AgentWork 开源社区（16.4万字/502截图/千万曝光先例）验证了「公开建造+开源+社区」模式。四个可搬部件：①具体的人类瞬间开场（我们的版本：WhatsApp 问题）→拉远到「AI 时代稀缺真实经验」立论；②四词标准；③「把 X 变成 Y」slogan 公式；④真实验证量（卡点/案例/信源/截图数）作为信任弹药。活动后可向其社区共建/投稿（上游分发渠道）。

**Growth OS 四词标准：真卡点 · 真跑通 · 真交付 · 真边界**（需求来自真实的人 / 过程可复现 / 结果可带走 / 失效处公开）

**Slogan：把一个人的增长部门，变成所有人都能开的方法。**

## 四、v0.1 "正常运转"验收标准

- [ ] 输入端：表单上线，T-14 内采集 ≥20 条需求/卡点（结构化入库，含 0-1/1-10 打标）
- [ ] 处理端：≥5 个模块成型（含 SOP/Prompt），≥3 个案例完成自动化拆条
- [ ] 输出端：≥10 条 build in public 帖；OS 可被 AI 检索问答（现场 demo 通过）
- [ ] 回流端：≥3 名贡献者；活动反馈 ≥10 条进入 v0.2 roadmap
